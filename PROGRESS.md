### 07.10.2026 — F10: инициализация проекта

Ветка плагина `fix/project-init`, не закоммичено, не собиралось (нет Windows / dotnet). Проверять в Revit.

- Существующий `.rvt` заявки больше не затирается: перед сохранением переименовывается в `имя.backup-дата.rvt`, при ошибке init возвращается на место. Раньше SaveAs затирал рабочий проект, а откат удалял файл совсем.
- Выбор заявки прошлого запуска сбрасывается, если открытый файл не инициализирован. Раньше старая заявка показывалась как привязанная, поиск был скрыт.
- После init Revit больше не закрывается (08.10.2026): плагин закрывается, Revit открывает новый проект, остальные файлы без несохранённых правок закрываются. Если открыть не вышло — сообщение с путём к файлу. `ProjectPostInitExitService` → `ProjectPostInitOpenService`. Открытие вызывается прямо из команды: из Idling Revit запрещает переключать активный документ («Switching active documents is not allowed during API event handling»). flat_num с точкой в конце («67.») давал папку с точкой, которую Windows отрезает, — точки в конце имени теперь убираются.
- Окно хаба не закрывается крестиком / Alt+F4 во время init и re-sync.
- Скорость: проверка SR_ID кэшируется по файлу (путь + время + размер), при init RFA и `surfaces.rvt` повторно не открываются. Между семействами окно перерисовывается, «Отмена» работает и во время импорта. Превью не «висит» на проверке.
- Фоновое скачивание останавливается при закрытии превью и при открытии нового; манифест кэша сохраняется и при отмене.
- «Продолжить без исправления» пропускает проблемные материалы (в том числе не скачанные) и грузит остальные.
- Если транзакция импорта surface откатилась, материалы отмечаются как ошибка, а не «загружено».
- Подгрузка карточки заявки берёт только точное совпадение `client_request_id`.
- Материалы (08.10.2026, вместо поля `in_tk`): SQL `read_revit_material_by_client_request` отдаёт только ТК заявки — строки ТК и элементы их наборов. Материалы набора (preset_kit) вне ТК больше не приходят ни в init, ни в «Материалы Revit». Плагин для этого не меняется. dev_prod, материалы с моделью: 2988849 — 15 → 14, 3071538 — 21 → 16.
- Элементы наборов ТК с моделью, которых нет в preset_kit, раньше не приходили вовсе, теперь приходят (6 заявок из последних 3000).

### 07.10.2026 — сборка под 2025 и 2027, адрес API для разработки

Ветка плагина `feature/tk-material-flags`, не закоммичено, не собиралось (нет Windows / dotnet).

- `build/RevitApi.props` подключён в оба проекта. API Revit 2025 берётся из установленного Revit, иначе из NuGet `Nice3point.Revit.Api.RevitAPI` / `RevitAPIUI` `2025.*` (только для компиляции, `ExcludeAssets=runtime`). Деплой `-p:DeployToRevit=true` идёт в `Addins\2025` и `Addins\2027`, годы задаются через `-p:RevitDeployYears=…`.
- `.addin` с относительным путём (`SmartRemont\SmartRemont.ExportRooms.dll`): один манифест подходит для любого года, установщик продолжает работать.
- Для сервера плагин всегда Revit 2025 (`PluginVersionCheckService.RevitYear`).
- API, удалённого в Revit 2026+ (`ElementId.IntegerValue`, `new ElementId(int)`), в коде нет. Остальные отличия 2027 проверяются только запуском.
- Адрес API: секретная панель в окне входа (5 кликов по чипу «Версия» за 3 с): поле, пресеты localhost:8000 / тест / прод, сброс. Порядок приоритета: панель → `apiOriginUrl` в `app.config` → `useTestApi`. При смене адреса сессия сбрасывается, чтобы токен не ушёл на другой сервер. Пока адрес задан, под шапкой окна видна жёлтая строка «API: … (задан вручную)».
- Сборка с адресом: `-p:ApiOriginUrl=http://localhost:8000` записывает его в `SmartRemont.ExportRooms.dll.config`. В `app.config` появился ключ `apiOriginUrl` с пустым значением, пустое игнорируется.
- Чтобы попасть в окно входа, когда сессия уже есть: «Выйти» в окне поиска заявки.
