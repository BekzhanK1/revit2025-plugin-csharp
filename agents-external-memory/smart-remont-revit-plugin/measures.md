# Замеры по коду (из модели Revit)

**Экран:** «Замеры по коду» (`RoomMeasurementsFromCodeWindow`)  
**Сервис:** `SBS/Services/RoomMeasurementsFromCodeService.cs`  
**Маппинг param_code:** `SBS/Services/RoomMeasurementsElementMapping.cs`  
**Модели:** `SBS/Models/RoomMeasurementsModels.cs`

Отдельный режим от замеров **из ведомостей** — см. [ROOM_MEASUREMENTS_MAPPING.md](ROOM_MEASUREMENTS_MAPPING.md).

---

## Общий алгоритм сбора

```text
Collect(doc)
  │
  ├─ Фаза: «После монтажных работ» (или первая в проекте)
  │
  ├─ Помещения: OST_Rooms, Area > 0, ROOM_PHASE = выбранная фаза
  │             сортировка: номер → имя
  │
  ├─ Предрасчёт по всему документу (один проход):
  │     • площади проёмов (двери + окна) по комнатам
  │     • количество межкомнатных дверей
  │     • количество двустворчатых дверей
  │     • площадь напольной плитки
  │     • площадь фартука (одно значение на всю квартиру)
  │
  └─ Для каждого помещения — 7 параметров (см. ниже)
       → RoomMeasurementsSnapshot { Rooms[], Sources[] }
```

**Единицы:** метры (м), квадратные метры (м²). Округление до 2 знаков (`Math.Round(..., 2)`).

**Имя помещения в UI/API:** `{ROOM_NAME} ({ROOM_NUMBER})`, если оба заданы; иначе только имя или номер.

**Сопоставление имён помещений** (`RoomNameMatcher`): базовое имя без суффиксов «№2», « 2», «(1)».  
Примеры: «Кухня №2» → «Кухня», «Гостиная (3)» → «Гостиная».

---

## Выбор фазы

`RoomAreaService.GetPreferredPhase(doc)`:

1. Фаза с именем **«После монтажных работ»** (без учёта регистра).
2. Если такой нет — **первая** фаза в проекте (по алфавиту).

Все привязки дверей (`FromRoom` / `ToRoom`), границы помещений и `GetRoomAtPoint` используют эту фазу.

## Параметры замеров

| param_code | Название | Ед. | Ограничение по помещению |
|------------|----------|-----|--------------------------|
| `PERIMETER_FLOOR` | Периметр по полу (за минусом дверей и проёмов) | м | все |
| `PERIMETER_ROOF` | Периметр по потолку (полный) | м | все |
| `DOOR_CNT` | Количество межкомнатных дверей | шт | все |
| `DOUBLE_DOOR` | Двустворчатая дверь | шт | только **Гостиная** |
| `PLITKA_AREA` | Плитка в прихожей или кухне | м² | только **Прихожая**, **Кухня** |
| `APRON_AREA` | Площадь фартука на кухне | м² | только **Кухня** |
| `WALL_AREA_MINUS` | Площадь стен за минусом дверей, проёмов и окон | м² | все |

Если параметр не применим к помещению или значение = 0 — в строке помещения поле `param_value` = `null`.

## PERIMETER_FLOOR — периметр по полу

**Цель:** длина плинтуса по полу с вычетом ширины дверных проёмов.

### Шаг 1. Брутто-периметр

```
grossM = SumBoundaryPerimeterM(room, Finish)
         или, если 0:
         GetPerimeterM(room)   // BuiltInParameter.ROOM_PERIMETER
```

**SumBoundaryPerimeterM:** сумма длин всех сегментов контура помещения с `SpatialElementBoundaryLocation.Finish` (отделка).

### Шаг 2. Вычет дверей

Для каждой двери (`OST_Doors`), у которой `FromRoom` или `ToRoom` = текущее помещение:

```
widthM = DOOR_WIDTH (в метрах)
deductM = Σ widthM
netFromGross = max(0, grossM − deductM)
```

Учитываются **все** двери на границе комнаты (включая входную), не только межкомнатные.

### Шаг 3. Защита от двойного вычета

В части моделей контур Finish уже **не включает** двери (разрывы в контуре):

```
если boundaryM > 0 и deductM > 0 и boundaryM ≤ netFromGross + 0.15:
    netM = boundaryM          // двери уже учтены в контуре
иначе:
    netM = netFromGross
```

**Результат:** `netM` (м), округление до 0.01.

---

## PERIMETER_ROOF — периметр по потолку

**Цель:** полный периметр по потолку **без** вычета дверей.

```
1. boundaryM = SumBoundaryPerimeterM(room, Finish)
2. если boundaryM > 0 → вернуть boundaryM
3. иначе roomPerimeterM = ROOM_PERIMETER → вернуть его
4. иначе null
```

Двери и проёмы **не вычитаются**.

---

## DOOR_CNT — межкомнатные двери

**Цель:** количество полноценных межкомнатных дверей (не проёмов).

### Условия учёта двери

Дверь попадает в счётчик, если **все** условия выполнены:

1. `FromRoom(phase)` и `ToRoom(phase)` **оба заданы**.
2. Оба помещения — из списка квартирных комнат (Area > 0, та же фаза).
3. Тип **не** является «проёмом» (`IsCountableInteriorDoor`):
   - в имени типа, семейства или экземпляра есть «проем» / «проём» (без учёта регистра).

### Распределение

Одна дверь между двумя комнатами **+1** в обе комнаты (и в «Гостиная», и в «Спальня»).

**Результат:** целое число; `null`, если 0.

---

## DOUBLE_DOOR — двустворчатые двери

**Применяется только к помещениям с базовым именем «Гостиная».**

Подмножество логики `DOOR_CNT` + фильтр `IsDoubleLeafDoor`:

```
двустворчатая, если:
  • DOOR_WIDTH > 1000 мм
  или
  • в имени типа есть: «дв.», «дв », «двуств», «2-ств»
```

Те же правила межкомнатности и исключения проёмов, что у `DOOR_CNT`.  
Счётчик также **+1 в обе** смежные комнаты; в таблице значение показывается только у «Гостиная».

---

## PLITKA_AREA — напольная плитка

**Применяется только к «Прихожая» и «Кухня».**

### Источник элементов

Категория `OST_Floors` (экземпляры полов).

### Фильтр «это плитка»

Параметр **«Модель»** на экземпляре или типе = **«Напольная плитка»** (без учёта регистра).

### Привязка к помещению

1. Центр bounding box пола (XY), Z = min + 0.1 м.
2. `doc.GetRoomAtPoint(pt, phase)` — комната должна быть в списке квартирных.

### Площадь

```
areaM2 = HOST_AREA_COMPUTED (м²)
         или, если 0:
         ERBO_Площадь
```

**Результат:** сумма площадей всех подходящих полов в комнате.

---

## APRON_AREA — фартук кухни

**Применяется только к «Кухня».**  
Одно **общее** значение на всю квартиру — одинаковое для всех строк «Кухня».

### Приоритет 1: ведомость

```
RoomMeasurementsService.TryGetApronAreaFromSchedule(doc)
  → ViewSchedule «Спецификация фартука кухни»
  → сумма колонки «Площадь» / «Площадь, м²»
  → привязка к FixedRoomName = «Кухня»
```

Если ведомость найдена и сумма > 0 — используется она.

### Приоритет 2: стены по ERBO

Если ведомости нет:

```
для каждой стены (OST_Walls):
  ERBO_Помещения (экземпляр или тип) ≈ «Кухня»
  areaM2 = ERBO_Площадь
  TotalAreaM2 += areaM2
```

**Результат:** суммарная площадь (м²).

---

## WALL_AREA_MINUS — площадь стен минус проёмы

**Цель:** площадь отделки стен = периметр × высота − площади дверей и окон.

### Периметр и высота

```
perimeterM = ROOM_PERIMETER (м)
heightM    = RoomAreaService.GetWallHeightM(room, doc)
```

**Высота потолка** (`GetCeilingHeightM`):

1. По стенам контура Finish: высота каждой уникальной стены → **мода** (наиболее частая высота, при равенстве — большая).
2. Иначе: верхний/нижний уровень помещения (`ROOM_UPPER_LEVEL` − base level).
3. Иначе: `UnboundedHeight` или `ROOM_HEIGHT`.

Допустимый диапазон: 0.01 … 50 м.

### Брутто-площадь

```
grossM2 = round(perimeterM × heightM, 2)
```

### Вычет проёмов

Предрасчёт `CollectOpeningAreasByRoom`:

**Двери** — для каждой двери с площадью > 0:

```
areaM2 = ERBO_Площадь
         или width × height (DOOR_WIDTH × DOOR_HEIGHT)
```

Площадь добавляется в **обе** комнаты (`FromRoom` и `ToRoom`), если они в списке.

**Окна** — площадь добавляется **одной** комнате:

```
areaM2 = ERBO_Площадь или WINDOW_WIDTH × WINDOW_HEIGHT
```

Привязка окна (`FindRoomForWindow`):

1. Параметр `ERBO_Помещения` на окне → match по базовому имени.
2. Иначе: точка окна + смещение 0.4 м по `FacingOrientation` / против → `room.IsPointInRoom`.
3. Иначе: `GetRoomAtPoint`.

*(Окно не привязывается по граничной стене — чтобы общая стена Гостиная/Балкон не давала лишние окна в обе комнаты.)*

### Итог

```
openingsM2 = сумма площадей проёмов в комнате
wallAreaM2 = max(0, grossM2 − openingsM2)
```

**Результат:** `null`, если `perimeterM ≤ 0` или `heightM ≤ 0`.

## Вспомогательные функции

| Функция | Назначение |
|---------|------------|
| `GetPerimeterM` | `ROOM_PERIMETER` → метры |
| `SumBoundaryPerimeterM` | сумма длин сегментов контура |
| `GetDoorWidthM` | `DOOR_WIDTH` → метры |
| `GetHostAreaM2` | `HOST_AREA_COMPUTED` или `ERBO_Площадь` |
| `GetParameterAreaM2` | числовой или текстовый параметр площади |
| `GetOpeningAreaM2` | `ERBO_Площадь` или width × height |
| `BuildOpeningLabel` | «дверь/окно {Mark}» или просто «дверь»/«окно» |
| `GetDoorRoom` | `get_FromRoom(phase)` / `get_ToRoom(phase)` |

### Парсинг чисел из текста

Regex: `[-+]?\d+(?:[.,]\d+)?`, invariant culture, запятая → точка.

## Блок «Источники» в UI

Для каждого `param_code` формируется `RoomMeasurementSourceInfo`:

| Поле | Значение для «по коду» |
|------|------------------------|
| `schedule_name_expected` | описание алгоритма из `RoomMeasurementsElementMapping` |
| `schedule_name_found` | `фаза «{имя фазы}»` |
| `Found` | есть хотя бы одно помещение с ненулевым значением |
| `Message` | построчная расшифровка расчёта по каждому помещению |

Пример сообщения для `PERIMETER_FLOOR`:

```text
Гостиная (1): контур Finish 12.34 м − двери 1.80 м (дверь D-01 0.90 м, дверь D-02 0.90 м) = 10.54 м
```

## Отличия от замеров по ведомостям

| Аспект | По коду | По ведомостям |
|--------|---------|---------------|
| Источник | Revit API (комнаты, двери, полы, стены) | `ViewSchedule` + парсинг таблиц |
| `MOLDING_PERIMETER` | **нет** | есть |
| `WALL_AREA_MINUS` | периметр × высота − проёмы | сумма из 2 ведомостей (обои + балкон) |
| `APRON_AREA` | ведомость **или** стены ERBO | только ведомость |
| `PERIMETER_FLOOR` | контур − ширина дверей | «Спецификация плинтуса» |
| Хрупкость | геометрия, фаза, параметры ERBO | имена ведомостей и колонок |
