# DECISIONS — Plugin UI Redesign

## #1 — Поиск только по remont_id

**Решение:** убрать режим «По ID заявки» с HomeWindow.

**Почему:** упрощение UX; backend `quick_search` поддерживает оба режима, но продукт хочет один сценарий.

**Follow-up:** если понадобится заявка — отдельное поле или deep link, не radio.

---

## #2 — Переход в hub по клику на карточку

**Решение:** single click на `ListBoxItem` → `SelectedRemont` + `DialogResult=true` + `Close()`.

**Альтернатива отвергнута:** кнопка «Продолжить» — лишний шаг.

---

## #3 — Скрытие vs удаление пунктов меню

**Решение:** `Visibility=Collapsed` + TODO-комментарий; handlers и окна **не удалять**.

**Почему:** быстрый возврат функций без восстановления кода.

---

## #4 — «ДС на изменение ТК» = RoomMaterialsWindow

**Решение:** переименовать `RoomMaterialsButton`; удалить stub `DsTkChangeButton`.

**Почему:** один рабочий экран уже есть; stub «Скоро» путает с новым названием.

---

## #5 — Debounced auto-search

**Решение:** phase 2 (не блокер эпика).

**Phase 1:** поле + Enter; кнопку «Найти» можно оставить secondary или убрать — на усмотрение task-02.

---

## #6 — Ширина окон

**Решение:** Home 900 px, Hub 960 px default.

**Почему:** больше места для hero header и длинных названий функций на русском.
