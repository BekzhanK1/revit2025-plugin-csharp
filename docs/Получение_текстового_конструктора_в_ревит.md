# Текстовый конструктор (client_material) по remont_id

  

Материалы ТК заявки — те же строки, что вкладка `requests/{id}?tab=textConstructor`.

  

## SQL

  

| Функция | Назначение |

|---------|------------|

| `public.read_client_material_by_remont(cur, remont_id_)` | `client_request_id` через `utils.get_client_request_id_by_remont`, строки `public.read_client_material` → JSON-массив `data` |

  

```bash

psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f sql/client-material/read_client_material_by_remont.sql

```

  

---

  

## HTTP API (для Revit-плагина)

  

### Запрос

  

```http

GET /common/client_material/tk/read/?remont_id={remont_id}

Authorization: Bearer {access_token}

Accept: application/json

```


  

**Query-параметры**

  

| Параметр | Тип | Обязательный | Описание |

|----------|-----|--------------|----------|

| `remont_id` | integer | да | ID ремонта из Revit / MySpace (`remont_tab.remont_id`), > 0 |

  

**Право:** `OA__RemontFormTabulation` (JWT пользователя MySpace).

  

### Успешный ответ — HTTP 200

  

Обёртка MySpace API (всегда проверять `status === true`):

  

```json

{

  "status": true,

  "error": null,

  "remont_id": 12345,

  "client_request_id": 2995240,

  "data": [ /* ClientMaterialRow[] */ ]

}

```

  

| Поле корня | Тип JSON | Nullable | Описание |

|------------|----------|----------|----------|

| `status` | boolean | нет | `true` — успех |

| `error` | string \| null | да | при успехе всегда `null` |

| `remont_id` | number | нет | эхо запроса |

| `client_request_id` | number \| null | да | заявка по ремонту; `null` если ремонт не найден |

| `data` | array | нет | строки материалов; пустой массив `[]`, если материалов нет |

  

### Элемент массива `data[]` — `ClientMaterialRow`

  

Каждый объект — одна строка «Текстового конструктора» (комната + конструктив + материал/набор).

  

#### Поля для парсинга в плагине (рекомендуемые)

  

| Поле | Тип JSON | Nullable | Описание |

|------|----------|----------|----------|

| `client_material_id` | number | нет | PK строки ТК |

| `client_request_id` | number | нет | заявка |

| `room_id` | number | да | комната |

| `room_name` | string | да | название комнаты (plain text) |

| `work_set_id` | number | да | конструктив |

| `work_set_name` | string | да | **может содержать HTML** (`<br>`, текст про ДС) |

| `material_id` | number | да | материал (если не набор) |

| `material_name` | string | да | **может содержать HTML** (название + кол-во + предупреждения) |

| `material_set_id` | number | да | ID набора; `null` если одиночный материал |

| `set_name` | string | да | название набора |

| `set_materials` | string | да | состав набора, **HTML** (`<div>`, `<br>`) |

| `photo_url` | string | да | URL фото материала/набора |

| `is_optional` | number | нет | `1` — опциональный, `0` — нет |

| `optional_name` | string | да | `"Да"` или `""` |

| `material_cnt` | number | да | количество материала |

| `material_type_id` | number | да | тип материала |

| `material_type_name` | string | да | название типа |

| `preset_material_type` | string | да | тип из подбора (enum в БД) |

| `ds_wset_id` | number | да | > 0 — строка из ДС изменения ТК |

  

#### Дополнительные поля из `client_material_tab` (могут пригодиться)

  

| Поле | Тип JSON | Описание |

|------|----------|----------|

| `formula_material` | string \| null | формула расчёта |

| `consumption_material` | number \| null | расход |

| `formula_material_result` | number \| null | результат формулы |

| `work_set_cnt` | number \| null | кол-во по конструктиву |

| `material_cnt_pieces` | number \| null | кол-во в штуках |

| `material_cnt_standard` | number \| null | нормативное кол-во |

| `preset_material_price` | number \| null | цена из подбора |

| `calc_type_id` | number \| null | тип расчёта |

| `material_usage_type_id` | number \| null | тип использования |

| `rowversion` | string \| null | timestamp ISO |

  

> Список полей в `data[]` = все колонки `client_material_tab` + вычисляемые поля SP `read_client_material`. Новые колонки таблицы могут появиться в ответе без смены версии API.

  

#### HTML в строках

  

SP отдаёт часть полей с разметкой (как в веб-UI):

  

| Поле | Пример | Рекомендация для плагина |

|------|--------|--------------------------|

| `work_set_name` | `"Плитка<br>(Набор ds_id=12345)"` | strip tags / заменить `<br>` → `\n` |

| `material_name` | `"Ламинат / 25 м²<br/><b>..."` | strip tags для отображения |

| `set_materials` | `"123 / Клей / 5 кг<div class=\"hr\">..."` | strip tags или WebView |

  

Сортировка строк в БД: `room_id`, `work_set_id` (как на вкладке).

## Ошибки

  

| Ситуация | HTTP | Тело (типично) |

|----------|------|----------------|

| Нет / невалидный JWT | 401 | `{ "status": false, "error": "..." }` |

| Нет права `OA__RemontFormTabulation` | 403 | `{ "status": false, "error": "..." }` |

| Нет query `remont_id` | 400 | `Field 'remont_id' is required` |

| `remont_id` не integer или ≤ 0 | 400 | сообщение валидации |

  

При `status === false` массив `data` может отсутствовать — не парсить как успех.

## Псевдокод парсинга (C# / Revit)

  

```csharp

var url = $"{baseUrl}/common/client_material/tk/read/?remont_id={remontId}";

var json = await GetJsonAsync(url, bearerToken);

  

if (json["status"]?.Value<bool>() != true)

    throw new ApiException(json["error"]?.ToString());

  

int? clientRequestId = json["client_request_id"]?.Type == JTokenType.Null

    ? null

    : json["client_request_id"]?.Value<int>();

  

var rows = json["data"]?.ToObject<List<ClientMaterialRow>>() ?? new();

  

foreach (var row in rows)

{

    var room = row.RoomName;

    var workSet = StripHtml(row.WorkSetName);

    var material = StripHtml(row.MaterialName);

    var isOptional = row.IsOptional == 1;

    // ...

}

```

  

**Ключ сопоставления с моделью Revit:** чаще всего `room_name` (normalize trim/lower) + `work_set_name` / `material_id`.

## Альтернатива (если уже есть `client_request_id`)

  

```http

GET /client_request/{client_request_id}/client_material/tk/read/

```

  

Ответ другой по форме — массив **блоков** прав:

  

```json

{

  "status": true,

  "data": [

    {

      "grant_code": "OA__RemontFormClientMaterialBlock",

      "grant_name": "Текстовый конструктор",

      "data": [ /* те же ClientMaterialRow */ ]

    }

  ]

}

```

  

Для плагина с `remont_id` используйте **`/common/client_material/tk/read/`** — плоский контракт без обёртки grant-блоков.
